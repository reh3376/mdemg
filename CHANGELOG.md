### Fixed

- **`docker` CLI unresolvable under the launchd minimal PATH — server-runtime shellouts silently failing** (2026-06-08). The native server (launchd) inherits `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, which excludes the Docker Desktop symlink (`/usr/local/bin/docker`). Two server-runtime `docker` shellouts failed with "executable file not found in $PATH": (1) Neo4j container CPU/mem stats logged an ERROR every 60s and left the `neo4j_container_*` gauges empty (so the `neo4j_high_cpu/_memory` alert rules had no data); (2) the TSDB backup scheduler's `docker compose pg_dump` failed with only a `slog.Warn`. The data plane was never affected — Neo4j (Bolt) + TSDB (pgx) connect over mapped TCP ports, not the docker CLI. Fix: new `internal/dockerbin` resolver (`MDEMG_DOCKER_BIN` env → `exec.LookPath` → well-known install locations → graceful unavailable), wired into both shellouts; the perpetual ERROR downgraded to a one-shot WARN when docker is genuinely absent; a sane `PATH` added to the launchd server plist template. Live-verified: container gauges now land in `metric_samples`; backup resolves docker under a simulated minimal PATH. (`export-auto` was **not** a victim — it exports via network SQL, not docker.)

- **`neighbor_node_ids` serialized as `null` (not `[]`) for an empty neighborhood — caught in EVENTGRAPH-CLI-001 live contract testing** (2026-06-08). `eventgraph.walkNeighborhood` returns a nil slice when the seed has no neighborhood (e.g. an unknown seed), which JSON-marshals to `null`, while the sibling `events` field was already initialized to `[]`. Both are array fields and must serialize consistently — `null` breaks any consumer asserting an array type (incl. the new UATS contract's `type_is array`). `EventsInGraphNeighborhood` now coalesces the nil slice to `[]string{}`; `TestFederationResult_EmptyArraysNotNull` pins the contract. Standard Go unit tests missed it (they don't marshal the empty result); the live UATS happy-path against the running server caught it immediately — its own fix-commit per the live-smoke precedent.


- **Follow-up C — `/v1/jiminy/latest` JSON control-char escaping: investigated, closed as NON-ISSUE** (2026-06-08). The last open item from the RRF-SCALE-001 live-smoke triage. Determined to be a client-side shell artifact, **not** a server bug — no code change. Evidence: `writeJSON` uses `encoding/json` (`json.NewEncoder().Encode`) which always escapes control chars; the synthesized guidance narrative is double-`StripControlChars`'d (synthesizer + service); and `prompt-context.sh` already strips control chars via `perl` before `jq` (with `2>/dev/null` + `// empty` fallbacks). The hook's exact `guidance_id` extraction returns correctly live, and 5 rapid `/latest` fetches all parse as strict-valid JSON. **This closes the entire RRF-SCALE-001 follow-up triage (A → JIMINY-OUTCOME-001, B → GUIDANCE-SYNTH-001, C → non-issue); the guidance→feedback→outcome loop is fully functional end-to-end.** See `docs/development/followup-c-closure.md`.

- **Sprint GUIDANCE-SYNTH-001 — Fix guidance synthesis timeout (Follow-up B)** (2026-06-08). LLM guidance **synthesis failed on every production warm call** (`synthesis_error: context deadline exceeded`; 6/6 `jiminy.synthesize` errored), so the hook never delivered the synthesized guidance narrative — it fell back to static formatting. Root cause (measured): the hook's `/v1/jiminy/warm` path runs a background `Guide()` with a **hardcoded 30s timeout** (even though `JIMINY_TIMEOUT_MS=240s` is configured), inside which the per-node constraint classifier ran **serially** (`consulting.classify` ~1.55s avg × ~10 nodes ≈ 15s on cache-miss), leaving only ~15s for synthesis which needs 8–27s (max 27s) → deadline-exceeded every time.
  - **Fix 1 — parallelize the per-node classifier:** `consulting.findApplicableConstraints` now classifies candidates with **bounded concurrency** (`CONSULTING_CLASSIFY_CONCURRENCY`, default 4 to match llama-server `--parallel 4`; floor 1 = serial). Gate-first to fix a stable order, classify into position-indexed slots via a semaphore-bounded worker pool, then collect-in-order + dedup — **output is identical to serial** (Tier 1 determinism test). Extracted `constraintClassifierIface` so the concurrent path is unit-testable; Tier 1 `-race` clean.
  - **Fix 2 — config-drive the warm-compute timeout:** replaced the hardcoded 30s (`handlers_jiminy.go`) with `JIMINY_WARM_COMPUTE_TIMEOUT_MS` (default 90000) — headroom for the parallel classifier + a slow synthesis. No-hardcoding rule.
  - **Live verification:** the warm path now produces a synthesized narrative — `synthesis_used=true`, **no `synthesis_error`**, 1892-char augmentation. A fresh `jiminy.synthesize` call **succeeded at 50.7s latency** — it completed only because the budget is now 90s (would have died at 30s; even 60s was risky), validating the default. Both fixes needed: parallelizing alone wouldn't survive a 50s synthesis in 30s; raising the budget alone leaves guide calls slow.
  - **Tests:** Tier 1 (5, `-race`: parallel==serial determinism, parallel-faster, error→keyword fallback, score-gate preserved, concurrency default); Tier 2 integration (skip-on-empty + LLM-tolerant: warm path produces guidance without `synthesis_error`). No behavior regression — guidance still surfaces constraints + codes still attach (RRF-SCALE-001 + JIMINY-OUTCOME-001 intact). Sprint in `docs/development/guidance-synth-001/`.
  - **Note:** local-model synthesis latency is high (~50s for a ~1900-char narrative) — config-tunable via the budget / `JIMINY_GUIDANCE_OUTPUT_MAX_CHARS`; worth watching but the warm path is fire-and-forget so it doesn't block the hook. **Closes Follow-up B**; Follow-up C (`/v1/jiminy/latest` JSON control-char escaping) remains the last open item.

- **Sprint RRF-SCALE-001 — RRF score-scale consumer remediation (revives the dormant Jiminy guidance loop)** (2026-06-03). The Jiminy guidance→feedback→outcome loop had been silently inactive for ~9 weeks. Root cause: `internal/consulting/service.go` gated constraint/suggestion/conflict extraction on **hardcoded legacy-scale score thresholds** (`r.Score < 0.55`, `> 0.6`, `> 0.65`, `> 0.7`) calibrated for the legacy linear scorer. When Column-Voting RRF became the default scorer (Phase 13.1, ~2026-05-03), the fused-score scale dropped — strong semantic matches now top out ~0.49–0.58 — so every retrieved node fell below the gates, `consulting.Suggest` returned empty, and Jiminy synthesized no guidance → no `guidance_id` captured → no feedback → no constraint outcomes recorded. **Third instance of this bug class** (after EVENTGRAPH-001's RRF `Activation`-drop and the Hebbian no-op): downstream consumers hardcoding the retrieval-score contract that Phase 13.1 silently changed.
  - **Audit sweep** (`docs/development/rrf-scale-001/audit_findings.md`) catalogs all 12 post-RRF score/activation/confidence consumers: 4 High (the consulting constraint-gate cluster + confidence sigmoid), 5 Med (conflict gates + the already-config-driven minConfidence pre-filter), 3 Low (retrieval/jiminy.go Activation *display* gates — traced, always-additive at RRF scale, intentionally left with rationale), 2 None (a J17 trial score + trust-score clamp, not retrieval scores).
  - **Fix:** replaced the 7 hardcoded gates + the score→confidence sigmoid (`retrievalScoreMidpoint/Steepness` 1.5/1.5, in both `consulting/service.go` and `jiminy/retrieval_source.go` — they must stay in sync) with **config-driven, RRF-calibrated** values (no-hardcoding rule: the bug *was* a hardcoded value). 5 new knobs: `CONSULTING_CONSTRAINT_SCORE_FLOOR` (0.45), `CONSULTING_AUTHORITY_SCORE_FLOOR` (0.45), `CONSULTING_CONFLICT_SCORE_FLOOR` (0.45), `RETRIEVAL_CONFIDENCE_SIGMOID_MIDPOINT` (0.45), `RETRIEVAL_CONFIDENCE_SIGMOID_STEEPNESS` (8.0). All with zero-value fallbacks. Sigmoid recalibration maps a strong 0.5 match from 0.18 confidence (legacy) → 0.60.
  - **Key Epic-2 finding:** `keywordClassifyConstraint` has an *inner* authority gate that binds tighter than the outer constraint gate — so the authority floor must also be 0.45 or the binding gate re-rejects the strong-match band and the loop stays dormant. The RRF band (0.49–0.58) is too compressed to subdivide into tiers; the knobs stay separate so operators can raise any one independently.
  - **Considered + rejected:** gating on `NormalizedConfidence` percentile (Option A) — the live distribution showed it is a *positional* rank (spreads 100→0 even on uniform-score sets), so it would admit noise. Chose config-driven absolute thresholds (Option B), disclosed per `feedback_plan_options_pattern.md`.
