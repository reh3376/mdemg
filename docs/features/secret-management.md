# Secret Management

## Summary

**Feature**: Secret Management
**Summary**: System keychain integration so secrets don't need to live in plaintext `.env` files. Supports macOS Keychain, Linux secret-tool, and Windows Credential Manager with opportunistic fallback.

## Vision & Goals

Sensitive credentials (database passwords, API keys, JWT secrets) should not live in plaintext on disk. MDEMG's secret management provides a zero-config keychain layer that sits between config files and environment variables in the priority chain. This is critical for the repo-to-public roadmap — ensuring no secrets leak into the memory graph or git history.

## Current State

### Architecture

MDEMG stores and retrieves secrets from the platform's native keychain:

- **macOS**: Keychain (via Security.framework)
- **Linux**: secret-tool (D-Bus Secret Service API)
- **Windows**: Credential Manager

Keychain is **opportunistic** — if unavailable, MDEMG falls back silently to `.env` files and environment variables. No action is required; secrets in the keychain are simply an additional configuration layer.

### Workflow

Secrets from the keychain sit between YAML config and `.env` in the priority chain:

```
defaults -> .mdemg/config.yaml -> keychain -> .env -> env vars -> CLI flags
```

Higher-priority sources always win. If `NEO4J_PASS` is set as an env var, the keychain value is ignored.

These keys are automatically resolved to environment variables on server startup:

| Key | Environment Variable |
|-----|---------------------|
| `neo4j-password` | `NEO4J_PASS` |
| `openai-api-key` | `OPENAI_API_KEY` |
| `jwt-secret` | `AUTH_JWT_SECRET` |
| `linear-webhook` | `LINEAR_WEBHOOK_SECRET` |

Arbitrary keys are also accepted by `set-secret` and `get-secret`, but they won't be auto-resolved to env vars.

### Configuration

The default `.mdemgignore` generated by `mdemg init` includes `.env` and `.env.*` patterns, preventing accidental ingestion of secret files into the memory graph.

**Migration from .env:**

```bash
# 1. Store each secret
mdemg config set-secret neo4j-password
mdemg config set-secret openai-api-key

# 2. Remove the lines from .env (keep non-secret config)

# 3. Verify
mdemg config list-secrets
mdemg config validate
```

## Notes

### Known Limitations

- Arbitrary keys stored via `set-secret` are not auto-resolved to env vars — only the 4 known keys are mapped
- Values are never printed by `list-secrets` (security by design)

### Risks & Gaps

None identified.

### Future Improvements

- Auto-detection of secrets in `.env` files during `mdemg init` with migration prompt

## API Endpoints

None — secret management is CLI-only.

## CLI Commands

| Command | Description |
|---------|-------------|
| `mdemg config set-secret <key> [value]` | Store a secret (prompts for hidden input if value omitted) |
| `mdemg config get-secret <key>` | Retrieve a secret (exits code 1 if not found) |
| `mdemg config list-secrets` | List all known secret keys with stored/not-set status |

## Configuration Reference

| Env Var | Default | Description |
|---------|---------|-------------|
| `NEO4J_PASS` | - | Auto-resolved from keychain key `neo4j-password` |
| `OPENAI_API_KEY` | - | Auto-resolved from keychain key `openai-api-key` |
| `AUTH_JWT_SECRET` | - | Auto-resolved from keychain key `jwt-secret` |
| `LINEAR_WEBHOOK_SECRET` | - | Auto-resolved from keychain key `linear-webhook` |
