# Secret Management

Phase 97 adds system keychain integration so secrets don't need to live in plaintext `.env` files.

## Overview

MDEMG can store and retrieve secrets from the platform's native keychain:

- **macOS**: Keychain (via Security.framework)
- **Linux**: secret-tool (D-Bus Secret Service API)
- **Windows**: Credential Manager

Keychain is **opportunistic** — if unavailable, MDEMG falls back silently to `.env` files and environment variables. No action is required; secrets in the keychain are simply an additional configuration layer.

## Configuration Priority

Secrets from the keychain sit between YAML config and `.env` in the priority chain:

```
defaults → .mdemg/config.yaml → keychain → .env → env vars → CLI flags
```

Higher-priority sources always win. If `NEO4J_PASS` is set as an env var, the keychain value is ignored.

## Commands

### Store a Secret

```bash
# Provide value on command line
mdemg config set-secret neo4j-password mypassword

# Prompt for hidden input (recommended for sensitive values)
mdemg config set-secret openai-api-key
Enter value for 'openai-api-key': ****
```

### Retrieve a Secret

```bash
# Print to stdout (for scripting)
mdemg config get-secret neo4j-password

# Use in shell scripts
export NEO4J_PASS=$(mdemg config get-secret neo4j-password)
```

Exits with code 1 if the secret is not found.

### List Secrets

```bash
mdemg config list-secrets
```

Output:

```
KEY                  ENV VAR                   STATUS
---                  -------                   ------
jwt-secret           AUTH_JWT_SECRET           not set
linear-webhook       LINEAR_WEBHOOK_SECRET     not set
neo4j-password       NEO4J_PASS                stored
openai-api-key       OPENAI_API_KEY            not set
```

Values are never printed by `list-secrets`.

## Known Secret Keys

These keys are automatically resolved to environment variables on server startup:

| Key | Environment Variable |
|-----|---------------------|
| `neo4j-password` | `NEO4J_PASS` |
| `openai-api-key` | `OPENAI_API_KEY` |
| `jwt-secret` | `AUTH_JWT_SECRET` |
| `linear-webhook` | `LINEAR_WEBHOOK_SECRET` |

Arbitrary keys are also accepted by `set-secret` and `get-secret`, but they won't be auto-resolved to env vars.

## .mdemgignore Protection

The default `.mdemgignore` generated by `mdemg init` now includes `.env` and `.env.*` patterns. This prevents accidental ingestion of secret files into the memory graph.

## Migration from .env

To move secrets from `.env` to the keychain:

```bash
# 1. Store each secret
mdemg config set-secret neo4j-password
mdemg config set-secret openai-api-key

# 2. Remove the lines from .env
# (Keep non-secret config like NEO4J_URI, EMBEDDING_PROVIDER, etc.)

# 3. Verify
mdemg config list-secrets
mdemg config validate
```
