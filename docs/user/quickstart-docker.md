# Docker Deployment Guide

MDEMG runs as a Docker Compose stack. Docker Desktop (or Docker Engine) is the only prerequisite for running MDEMG locally.

## Prerequisites

- **Docker Desktop** (macOS/Windows) or **Docker Engine** (Linux) with Compose v2
- **OpenAI API key** (for embeddings) — or Ollama for local embeddings

Verify Docker is available:

```bash
docker compose version
```

## Quick Start

```bash
# Install MDEMG CLI (macOS)
brew install reh3376/mdemg/mdemg

# Initialize and start all services
cd /path/to/your/project
mdemg init --quick
```

This will:
1. Check Docker is running and has adequate resources
2. Scan for 6 free host ports (MDEMG, Neo4j Bolt/HTTP, TimescaleDB, Neural, Grafana)
3. Generate `.env` with port assignments and credentials
4. Generate `.mdemg/config.yaml` with Docker-appropriate defaults
5. Run `docker compose up -d` to start all 5 services
6. Wait for the MDEMG server health check

## Interactive Setup

For guided setup with API key prompt:

```bash
mdemg init
```

## Services

| Service | Preferred Port | Purpose |
|---------|---------------|---------|
| MDEMG server | 9999 | Core API server |
| Neo4j | 7687 (Bolt), 7474 (HTTP) | Graph database |
| TimescaleDB | 5433 (host) | Time-series metrics |
| Neural sidecar | 8100 | Reranking + NLI models |
| Grafana | 3000 | Observability dashboards |

**All ports are dynamically assigned.** `mdemg init` scans each preferred port and if it's in use, automatically finds a free alternative. There are no hardcoded defaults — this prevents conflicts with existing Neo4j, PostgreSQL, or other services on the user's machine.

## Port Configuration

Ports are stored in `.env` at the project root (auto-generated by `mdemg init`):

```env
COMPOSE_PROJECT_NAME=mdemg-myproject
MDEMG_PORT=9999
NEO4J_BOLT_PORT=7688       # 7687 was in use, auto-assigned 7688
NEO4J_HTTP_PORT=7474
TSDB_HOST_PORT=5433
NEURAL_PORT=8100
GRAFANA_PORT=3001           # 3000 was in use, auto-assigned 3001
```

Edit `.env` to change ports, then restart:

```bash
docker compose down
docker compose up -d
```

## Common Commands

```bash
# Service status
docker compose ps

# Follow logs
docker compose logs -f

# Follow logs for a specific service
docker compose logs -f mdemg

# Restart all services
docker compose restart

# Stop all services (data preserved)
docker compose down

# Stop and delete all data volumes
docker compose down -v
```

## Multi-Instance Deployment

Each project gets its own `COMPOSE_PROJECT_NAME` (derived from the directory name), enabling multiple MDEMG instances on the same machine with isolated ports and data volumes.

```bash
# Project A
cd /path/to/project-a
mdemg init --quick
# → COMPOSE_PROJECT_NAME=mdemg-project-a, ports auto-assigned

# Project B
cd /path/to/project-b
mdemg init --quick
# → COMPOSE_PROJECT_NAME=mdemg-project-b, different ports
```

## Grafana Dashboards

Grafana is available at `http://localhost:3000` (or your configured `GRAFANA_PORT`). Default credentials: admin / admin.

Pre-provisioned dashboards:
- **MDEMG Overview** — request rates, latencies, error rates
- **Neo4j** — query performance, memory usage, connection pools
- **Graph Topology** — node/edge counts, layer distribution
- **Jiminy** — guidance synthesis metrics
- **RSIC** — self-improvement cycle metrics

## Troubleshooting

### Docker resources insufficient

MDEMG requires at least 4 GB RAM and 2 CPUs allocated to Docker. Check via:

```bash
docker info --format '{{.MemTotal}}' | awk '{printf "%.1f GB\n", $1/1024/1024/1024}'
```

Increase via Docker Desktop > Settings > Resources.

### Port conflicts

If `mdemg init` reports port conflicts, edit `.env` manually and set free ports, then:

```bash
docker compose up -d
```

### API key missing

If using OpenAI embeddings, ensure `OPENAI_API_KEY` is set in `.env`:

```bash
echo 'OPENAI_API_KEY=sk-...' >> .env
docker compose restart mdemg
```

### Health check fails

Check MDEMG server logs:

```bash
docker compose logs mdemg
```

Common causes: Neo4j not ready yet (wait 30s after first start), missing API key, port conflict.

## Development Build

For local development (building the MDEMG image from source instead of pulling from GHCR):

```bash
# Build the image
docker build -f deploy/docker/Dockerfile.prod -t mdemg:latest .

# Edit docker-compose.yml: comment out 'image:' line, uncomment 'build:' block
docker compose up -d --build
```

## Migration from Native Installation

If migrating from a native MDEMG installation (`mdemg db start` + `mdemg start`):

1. Stop native services: `mdemg stop && mdemg db stop`
2. Your Neo4j data lives in Docker volume `mdemg_neo4j_data` — Docker Compose uses the same volume name
3. Run `mdemg init --quick` to switch to Docker Compose mode
4. Verify data: `curl http://localhost:9999/v1/admin/spaces`
